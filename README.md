# 행사 시간표 제작기

행사 시간과 필요한 인원만 정하면, 배치 초안부터 개인별 일정표까지 만드는 독립 정적 웹앱입니다. 회원가입·API 키·서버 DB가 필요하지 않습니다.

[공개 제작기 열기](https://erakeun.github.io/event-timetable-maker/) · [저장소](https://github.com/erakeun/event-timetable-maker)

## 주요 기능

- 행사·날짜·장소·역할·필요 인원과 진행 일정 관리
- 참여 가능/불가시간, 자격, 휴게·이동·시간 상한을 고려한 자동배정
- 부족 표시, 잠금, 수동 수정, 빈자리 재배정, 되돌리기
- 확정본 보존과 개정, JSON 백업/복원, XLSX·CSV·PNG·PDF/인쇄

## 실행

Node.js 22 이상을 사용합니다. 이 전용 프로젝트 디렉터리에서 실행하세요.

```sh
npm ci
npm run dev -- --port 5173
```

표시된 로컬 주소를 여세요. `index.html`을 파일로 직접 열면 모듈·Worker·IndexedDB가 정상 동작하지 않을 수 있습니다.

```sh
npm test
npm run build
npm run test:e2e
node scripts/check-subpath.mjs
```

E2E는 격리된 Chromium headless를 사용합니다. 처음 실행하는 기기에서는 `npx playwright install chromium`으로 테스트 브라우저를 준비하세요. 기존 Chromium을 사용할 때는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`에 실행파일 경로를 지정합니다. 개발 도중 HMR의 영향을 피하기 위해 E2E는 빌드 산출물의 별도 로컬 미리보기를 사용합니다. 실제 실행 횟수와 결과는 [QA 보고서](docs/qa-report.md)에 기록합니다.

## 사용 흐름

1. **새 행사 만들기** 또는 실제 사람이 없는 **예시로 체험하기**를 선택합니다.
2. 운영 날짜·시간, 장소·역할·필요 인원, 책임자 조건을 입력합니다. 자정을 넘기면 **다음 날 종료**를 체크합니다.
3. 참여자와 가능시간을 입력합니다. 기본은 미확인입니다. 확인한 사람만 **전체 운영시간 가능**으로 일괄 설정하고 불가시간을 추가하세요.
4. **자동배정 초안 만들기** 후 변경 미리보기를 보고 적용합니다. 기본 재실행은 빈자리만 채웁니다. 잠금, 선택 범위 재배정, 수동 수정과 Undo/Redo를 제공합니다.
5. **확인·출력**에서 오류와 부족을 해결하고 확정합니다. 확정본은 스냅샷으로 남으며 이후 편집은 새 개정 초안에서 합니다.
6. 전체·개인·장소·진행·변경된 사람만 출력할 수 있습니다. XLSX/CSV, 날짜·범위 PNG, 브라우저 **인쇄 / PDF로 저장**과 편집 재개용 JSON 백업을 제공합니다.

진행표만 필요한 경우 첫 화면의 **진행 시간표만 만들기**를 사용하세요. 연락 담당자는 시간을 점유하지 않으며, **해당 시간 전담** 담당자는 인력 배정과 중복을 검사합니다.

## 저장과 개인정보

- 현재 기기·브라우저의 IndexedDB에 저장합니다. 다른 기기로 옮길 때는 JSON 백업이 필요합니다. 브라우저 저장은 영구 백업이 아닙니다.
- 데이터 삭제, 비공개 모드, 공간 부족, 브라우저 오류로 자료가 사라질 수 있습니다. 저장 실패를 화면에 알리며 편집 중 자료를 유지합니다.
- 여러 탭이 같은 행사를 수정하면 revision을 한 트랜잭션에서 비교합니다. 늦은 쓰기를 거절하고 읽기 전용·최신 불러오기·사본 저장 경로를 제공합니다.
- 공용 PC 다음 이용자가 같은 브라우저의 자료를 볼 수 있습니다. 인증·암호화를 구현하지 않았습니다. 백업 후 **이 앱 저장자료 모두 삭제**를 이용하세요. 다른 앱의 DB/localStorage는 지우지 않습니다.
- 기본 출력은 가능시간 상세와 운영자 메모를 포함하지 않습니다. 내부용 메모 포함은 명시적 선택입니다. JSON에는 명단·가능시간·내부메모가 포함되므로 배포용 출력과 구분하세요.
- 사용자 입력을 외부 AI·분석·로그 서버에 보내지 않습니다. 계산은 브라우저 Worker에서 수행합니다. 오프라인 재접속을 보장하는 PWA는 구현하지 않았습니다.

## 자동배정 범위

정수 분과 반열린 구간 `[시작, 종료)`를 사용합니다. 실제 경계는 화면 눈금으로 반올림하지 않습니다. 불가 우선, 미확인 제외, 역할 자격, 책임자 포함 총원, 일별/전체/연속 상한, 휴게·이동, 전담 프로그램, 잠금을 검사합니다. 균등 배정은 실제 분과 유효 가능시간을 고려합니다.

결과는 재현 가능한 seed 기반 휴리스틱 초안입니다. 전역 최적해를 보장하지 않고, 탐색 중단이나 남은 부족을 전체 문제의 불가능 증명으로 표현하지 않습니다. 실행 후 같은 UI와 분리된 독립 검증기를 다시 실행합니다. 운영자가 정한 편성 조건을 검사하며 법적 적합성을 보장하지 않습니다.

## 정적 배포와 롤백

소스는 `main`, 공개 정적 파일은 `gh-pages` 브랜치에서 관리합니다. `npm ci`, `npm test`, `npm run build`, `npm run test:e2e` 검사를 통과한 `dist/`만 `gh-pages`에 반영하고 GitHub Pages가 게시합니다. 소스 push만으로 자동 빌드하지 않습니다. 저장소 Pages의 소스는 `gh-pages` 브랜치 루트입니다.

현재 배포 인증은 Actions workflow 변경 권한이 없어 브랜치 배포를 사용합니다. 이후 배포도 검증한 빌드만 반영해야 하며 배포 버전은 사이트의 `release.json`에서 소스 커밋으로 확인할 수 있습니다.

`base: './'`와 모듈 Worker 경로를 사용합니다. 공개 진입 주소는 `/event-timetable-maker/`이며 편집 단계는 페이지 내부 상태입니다. 행사별 공유 URL이나 서버 라우팅은 제공하지 않습니다.

롤백은 직전 검증된 커밋의 빌드를 다시 배포합니다. 브라우저 데이터는 배포와 별개이므로 백업을 먼저 확보하고 스키마를 낮추지 마세요. 현재는 schemaVersion 1만 읽으며 알 수 없는 버전은 원본을 유지하고 거절합니다.

같은 origin의 다른 앱과는 DB 이름만 다릅니다. 접두사는 보안 경계가 아닙니다. 민감자료를 다룰 실제 배포는 독립 origin을 우선 선택하세요.

## 백업과 복원

편집 화면의 **JSON 백업**으로 내려받고, 첫 화면의 **백업 불러오기**에서 파일을 선택합니다. 같은 행사 ID가 있으면 사본으로 복원합니다. XLSX·PDF·PNG는 배포용 출력이며 편집 상태 복원에는 JSON을 사용하세요. **브라우저 데이터를 삭제하면 저장 내용이 사라질 수 있으므로 중요한 행사표는 반드시 JSON 파일로 보관하세요.** 백업에는 명단과 내부메모가 포함됩니다.

## 브라우저와 알려진 제한

최신 데스크톱 Chromium 계열 브라우저 사용을 권장합니다. 로컬 검증은 Chromium 140에서 수행했고, 공개 사이트에서도 Chromium 140의 브라우저 시나리오 12개를 검증했습니다. 상세 결과는 QA 보고서에 구분해 기록합니다. 390·412px 모바일 크기는 Chromium 화면 검증이며 실제 휴대폰 검증과는 다릅니다. Safari·Firefox·실제 프린터·Microsoft Excel 앱 화면은 아직 검증하지 않았습니다.

자동배정은 최적해 보장이 없는 초안이며 운영자의 최종 확인이 필요합니다. 여러 기기 동기화, 로그인, 공동편집, 서버 저장, PWA는 제공하지 않습니다. 이미지 출력은 선택 범위와 크기 제한이 있으며 아주 큰 자료의 성능은 보장하지 않습니다. XLSX 라이브러리로 초기 JS 다운로드가 약 1.32MB입니다.

공개 소스는 로컬 검증 기준 `9fbb53a`에서 분리했습니다. 앱 소스와 배정 로직은 그대로이며 공개 안내·배포 설정·테스트 실행 경로만 정리했습니다. 생성된 검증 이미지·PDF·XLSX·백업·임시 파일과 기존 로컬 Git 이력은 공개 저장소에 포함하지 않습니다. 사용자 입력이나 백업 파일은 Git에 올리지 마세요.


## V1.1 사용 흐름 개선

- 진행표만 만들기는 **행사 설정 → 진행 시간표 → 확인·출력** 3단계입니다. 인력 배정이 필요해지면 `인력 배정도 필요하신가요?`에서 확장합니다. 기존 진행 일정은 유지합니다.
- 명단 자격은 쉼표·세미콜론·줄바꿈으로 구분합니다. 가져오기 검토에서 실제 태그, 원본 열 연결, 미반영 열, 오류를 확인하세요. 미반영 열이나 업데이트 영향이 있으면 확인 후 적용합니다. 기존 V1 백업의 태그를 자동으로 다시 해석하지 않으므로, 과거에 합쳐진 태그는 개인 화면에서 수정하거나 ID 업데이트로 다시 가져오세요.
- 명단의 체크박스로 사람을 선택한 뒤 **공통 근무조건 설정**을 펼치세요. 기본값은 기존 개인 조건 유지이며 빈칸은 변경하지 않습니다. 기존 값을 바꾸려면 덮어쓰기를 선택하고 변경 전후를 검토합니다. 기존 배정은 유지되어 새 조건 위반 시 수정 필요로 표시됩니다. 상단 되돌리기로 일괄 적용을 취소할 수 있습니다.
- 부족·오류 항목의 날짜·장소·역할과 후보별 검사 결과를 확인하고 해당 시간 또는 관련 설정으로 이동할 수 있습니다. 후보 검사는 현재 배정을 유지한 상태의 결과이며 가능한 모든 재편성을 탐색한 증명은 아닙니다.
- 모바일에서 배정을 선택하면 하단 편집 패널이 열립니다. 교체·잠금·해제를 수행하고 패널을 닫거나 되돌릴 수 있습니다.
- PNG/CSV/XLSX 파일명은 출력 유형·선택 대상·날짜·버전을 포함합니다. XLSX는 기존과 같이 여러 시트를 포함하며 선택 범위가 적용됩니다. PDF 기본 이름은 브라우저 인쇄 기능에 따라 달라질 수 있습니다.

저장 스키마는 V1과 동일한 1이며 V1 JSON 백업을 복원할 수 있습니다. 배정 정책, 확정 스냅샷, 잠금과 IndexedDB 충돌 보호는 유지합니다. 격자형 인쇄와 진행 순서 대량 붙여넣기는 후속 개선 후보입니다.
