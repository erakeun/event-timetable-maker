# 저장·가져오기·출력 규격

## 브라우저 저장과 실패 처리

- IndexedDB 이름: `project-mach-event-timetable-maker-v1`, DB 버전 1, object store `events`, key path `id`.
- 자료는 현재 origin의 현재 브라우저 프로필에만 저장한다. 네트워크 동기화, 사용자 인증, 암호화, 영구 보관을 제공하지 않는다. 이름 접두사는 다른 앱과의 충돌을 줄이는 수단이며 origin 보안 경계가 아니다.
- `saveEvent(event, expectedRevision)`은 단일 `readwrite` transaction 안에서 기존 revision을 읽고 비교한 뒤 저장한다. 새 ID 생성은 `null`을 요구하며 첫 revision은 0이다. 이후 저장은 1씩 증가한다. 같은 revision으로 동시 저장한 탭 중 하나만 성공하며, 삭제된 행사를 낡은 탭이 다시 저장하는 것도 거절한다.
- transaction 완료 이벤트 후에만 성공 Promise가 반환된다. 오류·quota·사용 불가·revision 충돌은 reject한다. 호출자가 보유한 편집 객체를 수정하거나 정상 저장본을 초기화하지 않는다. UI는 현재 편집 내용을 유지하고 백업·사본·새로 불러오기 경로를 표시한다.
- `listEvents()`는 구조가 유효한 항목만 반환한다. 손상 항목은 그대로 남기고 `getStorageWarnings()`로 제외 이유와 ID를 제공한다. `loadEvent()`는 같은 구조 검사를 통과해야 한다. 자동 마이그레이션은 없으며 알 수 없는 스키마는 거절한다.
- `clearEvents()`는 이 DB의 events store와 `event-timetable-maker:` 접두사의 localStorage 키만 삭제한다. 다른 앱의 DB와 localStorage를 전체 삭제하지 않는다.

## 전체 JSON 백업

루트 필드: `app: "event-timetable-maker"`, `schemaVersion: 1`, `appVersion`, `eventId`, ISO `savedAt`, `timezone: "Asia/Seoul"`, `event`. event에는 별도 ID로 연결된 날짜·장소·역할·수요·참여자·가능시간·배정·진행표·정책·확정 스냅샷이 포함된다.

전체 백업은 이름·팀·가능시간·운영자 내부메모·과거 확정본까지 포함하는 **편집용 자료**다. 공개 배포용 XLSX/CSV/PNG와 구분해야 한다. 파일 또는 백업 내용을 URL query/fragment로 공유하지 않는다.

검사 항목은 스키마·앱 식별·메타데이터 일치·필드 타입·시간 형식·정수 분·중복 ID·배열 크기다. 범위는 1900~2200년, 개별 시간 구간은 최대 366일이다. 초안의 누락된 장소/역할/참여자 참조와 편성 충돌은 수정 가능한 상태로 보존하며 공유 검증기가 오류로 표시한다. 참조 항목을 조용히 생성하거나 연결 배정을 삭제하지 않는다.

확정본은 더 엄격하다. 각 스냅샷은 확정 상태여야 하고 실제 공유 검증기의 오류·인원 부족·책임자 부족이 없어야 한다. 스냅샷 버전은 중복 없이 증가하고 데이터의 edition과 일치해야 한다. 현재 확정 상태는 해당 edition의 최신 스냅샷을 가져야 하며, revision·updatedAt을 제외한 내용이 스냅샷과 같아야 한다. 이는 앱 내부 실수와 손상을 찾는 검사이며 서명·위변조 방지 감사로그가 아니다.

선택 `logoDataUrl`은 PNG/JPEG base64 data URL만 허용한다. 파일 시그니처를 검사하고 디코딩 크기를 1MB로 제한한다. SVG, HTML, 원격 이미지 URL은 거절한다.

## 입력 형식과 적용

앱에서 다운로드하는 실제 XLSX 서식의 첫 시트가 입력 데이터이며, `작성안내` 시트에 필드 설명과 현재 행사의 ID 참고 목록을 넣는다.

| 자료 | 열 이름 |
| --- | --- |
| 명단 | `id,name,team,alias,tags,color,allowedRoleIds` |
| 가능시간 | `id,personId,date,start,end,nextDay,state` |
| 필요 인원 | `id,locationId,roleId,date,start,end,nextDay,count,leaderTag,leaderMin,phase` |

- CSV/TSV는 첫 행을 제목으로 사용한다. 쉼표 CSV, 탭 복사 표, 인용부호·인용부호 이스케이프·셀 안 줄바꿈을 처리한다. ID는 텍스트를 유지해 `0001`을 보존한다. 숫자형 ID는 선행 0을 알 수 없으므로 오류로 돌려보낸다. 동명이인은 ID가 다르면 별도 참여자다.
- 열 이름은 영문 필드 키 또는 한국어 표시 이름을 자동 매핑하며, 사용자가 각 필드를 다시 매핑할 수 있다. 적용 전 첫 8개 행 미리보기와 행별 오류를 표시한다.
- 문자열 날짜는 `YYYY-MM-DD`, 시각은 `HH:MM`이다. Excel의 숫자형 날짜 및 분 단위 시간 비율은 별도로 파싱하며 1900/1904 날짜 시스템을 구분한다. 분으로 정확히 표현되지 않는 초 단위 값, 모호한 시각·날짜는 거절한다. 시각을 눈금에 맞춰 반올림하지 않는다.
- `nextDay`는 `예/아니오`, `true/false`, `1/0`을 지원한다. 종료가 시작보다 이른데 다음 날이 명시되지 않으면 오류다. 파일 날짜·구간은 실제 행사 운영 범위 안에 있어야 한다.
- `state`: `가능/불가/미확인/선호` 또는 `available/unavailable/unknown/preferred`. 파일에 알려지지 않은 참여자 ID가 있으면 행 오류다. 선호와 가능 관계는 적용 후 공유 제약 검증기로 다시 검사한다.
- 역할 태그·허용 역할 ID 목록은 세미콜론(`;`) 또는 `|`로 구분한다. 색상은 `#20816a` 형태다. 앞뒤 공백을 제거하며 명단의 줄바꿈은 공백으로 정리한다.
- 추가는 이미 있는 ID를 거절하고, 업데이트는 없는 ID를 거절한다. 명단 업데이트는 매핑한 열만 수정하며 기존 가능시간·시간 조건·ID 연결은 유지한다. 전체 교체는 기존 참여자 제거·배정 해제·진행표 담당자 해제 등 영향을 먼저 표시한다. 과거 스냅샷은 변경하지 않는다.
- 가능시간 전체 교체는 전체 참여자의 가능시간을 교체한다. 파일에 없는 사람은 미확인 상태가 된다. 수요를 교체해도 기존 배정을 조용히 지우지 않으며 적용 후 공유 검증기 결과로 수정 필요를 알린다.
- 읽기·미리보기는 원본 이벤트를 변경하지 않는다. 오류가 있는 미리보기는 적용할 수 없다. 실제 적용은 deep clone에 수행하고 구조·용량·공유 제약을 다시 검사한다. UI에서 한 번의 Undo로 복원할 수 있는 단위로 전달한다.

## 한도

| 대상 | 한도 |
| --- | --- |
| 업로드·JSON 백업 파일 | 10MB |
| CSV/TSV/XLSX 데이터 | 10,000행, 100열 |
| XLSX 워크북 | 10시트, 첫 입력 시트 사용 |
| XLSX ZIP 메타데이터 | 1,000 내부 파일, 선언된 압축 해제 합계 50MB |
| 행사 데이터 | 참여자 500명, 장소 100개, 역할 100개, 수요 2,000개, 배정 20,000개, 진행 항목 2,000개 |
| 확정본·총 데이터 | 확정본 25개, 현재 자료와 확정본을 합쳐 50,000항목 |

한도는 과대 입력 방어용이며 이 크기 전체에 대한 성능 보장이 아니다. 실제 성능 검증은 QA 보고서의 7일·100명·10개 장소 시나리오에 한정한다. XLSX 압축 검사는 선언된 크기에 대한 사전 검사이며 임의의 적대적 압축 파일에 대한 완전한 자원 격리를 의미하지 않는다.

## 배포용 출력

- 전체·개인·장소/역할·진행표·변경된 사람만 출력할 수 있다. 사람/팀은 ID 목록으로 필터링하며 명시적인 빈 목록은 전체를 뜻하지 않는다. 날짜/범위는 실제 경계로 자르고 자정 넘김 행은 날짜별로 나누어 인쇄 페이지와 합계를 맞춘다.
- 총 배정 분과 일별 합계는 공유 `validateEvent` 계산을 사용한다. 인력표에는 전담 진행 행을 함께 넣어 총합의 근거를 확인할 수 있다. 진행표 전용 보고서의 총 배정 분은 전담 담당자의 점유 시간이며 단순 연락 담당은 포함하지 않는다.
- 변경본은 초안이면 마지막 확정본, 확정 상태이면 직전 확정본과 비교한다. 이름·별칭·팀, 배정 시간/장소/역할/잠금, 전담 진행 변경을 포함한다. 배정이 사라진 사람은 `배정 없음`으로 표시한다.
- 실제 XLSX ZIP 파일에 `행사정보`, `전체 배치`, `개인별 배치`, `시간 합계`, `부족·주의`, `행사 진행표`, `장소별 운영` 7개 시트를 작성한다. 표 제목·헤더·고정 행·필터를 갖추며 일반 Excel에서 셀을 편집할 수 있다. 편집 재개용 원본은 JSON 백업이다.
- 기본 출력은 가능시간 상세와 운영자 내부메모를 제외한다. 내부용 옵션을 선택했을 때만 진행표의 운영자 메모 열을 추가한다. 부족·주의 시트는 행사 전체의 검증 내용을 제공한다. XLSX에 수식 객체를 넣지 않고 사용자 텍스트를 문자열 셀로 작성한다. CSV는 `= + - @` 및 앞쪽 제어문자/공백 뒤 수식 시작문자에 작은따옴표를 붙여 수식 해석을 막는다.
- 브라우저 인쇄/PDF 및 PNG는 Review 화면의 실제 보고서에서 생성한다. PNG는 날짜를 선택하고 100행 이하로 제한한다. PWA나 완전 오프라인 재접속 지원을 구현했다는 의미는 아니다.

## 실제 I/O 검증 자료

`RECORD_IO_FIXTURES=1 npx vitest run tests/io.test.ts` 실행으로 `docs/qa/verified-public-export.xlsx`, `verified-editing-backup.json`, `verified-roster-template.xlsx`, `verified-availability-template.xlsx`, `verified-demand-template.xlsx`를 생성한다. 모두 가상 자료다. 테스트는 생성한 XLSX를 ExcelJS로 실제 다시 열어 ID·문자열 셀·시트·분 합계·내부메모 제외를 검사한다. 이 재열기 검사는 Microsoft Excel UI에서 직접 시각 검수했다는 의미는 아니다. 인쇄/PNG/브라우저 시각 검수 결과는 별도 QA 보고서를 따른다.
