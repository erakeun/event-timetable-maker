# 행사 시간표 제작기 V1 — 구현 규칙

이 문서는 현재 소스의 데이터·계산 정책을 설명한다. 실제 실행 증거와 브라우저/출력 검수 범위는 `qa-report.md`를 별도로 따른다. 계산 조건은 행사 운영자가 정하는 편성 조건이며 법적 근로 기준 적합성을 보장하지 않는다.

## 범위와 데이터

로그인이나 원격 명단 저장소 없이 하나의 브라우저에서 행사를 생성·편집한다. 인력 배치표가 주기능이며 진행표 전용 행사도 만들 수 있다. 행사, 날짜, 장소, 역할, 사람, 수요, 배정, 진행 항목에는 서로 독립적인 ID가 있다. 이름 변경은 ID를 바꾸지 않는다. 같은 이름의 다른 참여자는 별도 ID로 다룬다.

`EventData`는 `schemaVersion: 1`, `appVersion`, 행사 ID, `timezone: Asia/Seoul`, 생성·수정 시각, 저장 `revision`, 출력 `edition`, 초안/확정/보관 상태를 포함한다. 장소와 역할은 별도 모델이다. 수요는 장소 ID + 역할 ID + 정확한 시작/종료 + 총 필요 인원 + 책임자 태그/최소 인원으로 구성한다. 같은 장소·역할의 수요 구간 중복은 오류이며, 인원이 바뀌는 시각에서 구간을 나누어 입력한다.

장소 공유 프로그램은 여러 장소에서 병렬 진행할 수 있다. 같은 장소에서 진행 시간이 겹치면 두 항목 모두 장소 공유를 명시한 경우를 제외하고 경고한다. 담당자가 단순 연락 담당이면 점유시간에 포함하지 않는다. `dedicated: true`인 전담 진행자는 같은 사람의 배정과 함께 동시배정·가능시간·상한·연속시간·휴게·이동 검사 대상이다. 개인별 시간 합계에는 전담 진행 시간도 포함되며, 연락 담당 시간은 포함되지 않는다. 전담 진행 시간이 인력 수요를 대신 충족시키지는 않는다.

## 시간 표현

시간 계산은 한국 행사 달력에 맞춘 정수 분이다. 내부 숫자는 날짜를 UTC 달력 좌표로 변환한 뒤 시/분을 더한 **Asia/Seoul 벽시계 좌표**다. UTC 실제 시각을 의미하지 않으며 브라우저 로컬 시간대에 따라 변환하지 않는다. 해외 시간대나 DST 변환은 구현하지 않았다. 날짜 입력 범위는 1900~2200년이다.

모든 구간은 `[시작, 종료)`이다. 10:00–11:00과 11:00–12:00은 중복이 아니다. 종료가 빠르다고 익일로 추정하지 않는다. 사용자가 `다음 날 종료`를 선택해야 날짜에 1일을 더하며 화면에는 `+1일`을 표시한다. 자정 구간의 개인별 일일 합계는 실제 00:00 경계에서 분할한다. 예를 들어 23:30–익일 00:30은 총 60분이며 각 날짜 30분이다.

눈금은 5/10/15/20/30/60분 중 하나이며 기본 30분이다. 눈금은 표 표현에만 사용한다. 수요·가능시간·기존 배정·진행 항목의 실제 경계를 계산에 사용하고 분을 반올림하지 않는다. 자동배정은 눈금마다 사람을 교체하지 않는다. 최소 배정 길이 기본값은 30분, 권장 교대 길이는 120분이며 서로 독립이다. 같은 사람·장소·역할에서 맞닿은 구간은 하나의 연속 근무로 최소 배정 길이를 판단한다. 다른 역할로 바뀐 연속 근무도 개인별 최대 연속시간에는 포함한다.

## 가능시간과 개인 조건

미입력 시간은 미확인이다. 명시적 전체 운영시간 가능 설정은 실제 가능 구간을 생성한다. 같은 시각에 여러 입력이 겹치면 **불가 → 명시적 미확인 → 가능** 순으로 적용한다. 선호시간 자체는 가능 상태를 만들지 않으며, 반드시 명시적으로 확인된 가능시간의 부분집합이어야 한다. 선호와 불가가 겹치면 선호 조건이 잘못되었다는 오류를 표시한다. 배정 불가 날짜는 해당 날짜의 부분 구간에도 적용한다.

역할의 `requiredTags`는 모두 만족해야 한다. 개인의 `allowedRoleIds`가 비어 있으면 역할 태그 조건을 만족하는 역할을 허용한다. 비어 있지 않으면 그 목록으로 제한한다. 개인 최대 일일/전체/연속 배정시간을 비워 두면 해당 상한이 없다. 개인 최소 휴게시간을 비워 두면 별도 휴게 간격 하한은 없다. 장소 간 이동시간 기본값은 0분이다. 휴게는 두 근무 사이의 양수 간격에 적용하며 맞닿은 근무는 연속 근무로 판정한다. 장소가 바뀌면 맞닿은 근무에도 설정된 이동시간을 요구한다.

일일 최대시간은 운영일 레이블 대신 실제 달력 날짜를 기준으로 적용한다. 개인별 최소 배정시간은 희망(경고) 또는 필수(오류)로 나뉜다. 희망시간·선호시간·균형·장소 이동 최소화는 절대 조건을 완화할 수 없다.

## 검증기

`src/core/validate.ts`는 UI와 분리된 순수 검증기다. `canAssign`은 수동 후보와 자동 후보를 점진적으로 검사하며, `validateEvent`는 전체 상태를 다시 검사한다. 자동 결과는 독립적으로 전체 검증을 거친다. 입력 가져오기는 구조 검증과 제약 검증을 구분한다. 손상된 구조나 알 수 없는 스키마는 거절하고, 유효한 구조의 초안에 남아 있는 편성 문제는 수정 목록으로 보여 준다.

검사 항목은 유효한 정수 분·운영시간·참조 ID·중복 ID·행사/장소/역할/참여자 이름·역할 자격·미확인/불가·동시배정·최대시간·연속시간·휴게·이동·최소 배정 길이·수요 밖 배정·초과 인원·책임자·필수 최소시간이다. 수요가 없는 구간과 필요 인원이 0명인 구간에는 배정할 수 없다.

책임자는 총 필요 인원 안에서 센다. 총 3명, 책임자 최소 1명 조건이면 총 배정 3명 중 적어도 1명이 책임자여야 한다. 책임자 부족(`LEADER_SHORTAGE`)과 개인 필수 최소시간 부족(`HARD_MIN`)은 최종 집계 조건이다. 점진적 `canAssign`에서는 이 두 집계 오류를 적용하지 않아 먼저 일반 인원을 넣고 다음에 책임자를 채울 수 있다. 최종 검증에는 계속 남으므로 충족하지 않은 상태를 정상 확정할 수 없다.

운영자가 초과 인원을 명시적으로 허용하면 수동 초과는 경고로 기록한다. 자동 후보 추가는 그 정책과 관계없이 필요 인원을 초과할 수 없다. 기존 자동 배정만으로 필요 인원을 초과한 상태는 오류다.

필요 인분은 `필요 인원 × 구간 분`, 충족 인분은 `min(필요 인원, 고유 배정 인원) × 구간 분`, 부족 인분은 그 차이다. 책임자 부족은 별도 필드이며 인원 부족 인분에 다시 더하지 않는다. 장소별 합계와 전체 합계는 동일 검증 결과를 사용한다. 불가 등 하드 오류가 있는 기존 배정은 자동 삭제하지 않는다. 해당 사람의 배정시간과 자리 점유도 유지되므로 충족률 숫자만으로 유효한 확정을 주장해서는 안 된다.

부족 구간은 수요/배정뿐 아니라 가능·불가·미확인·진행 항목 및 자정 경계를 반영한다. 부족 설명의 후보 수는 해당 정확한 구간 전체에 대해 역할 자격과 가능시간을 만족하는 수다. 이 숫자가 다른 배정·휴게·상한까지 모두 반영한 가용 인원수는 아님을 표시한다. 책임자 후보 0명이라는 설명은 이 기준으로 실제 0명인 구간에만 사용한다.

## 자동배정 절차

`src/core/scheduler.ts`는 seed를 가진 결정적 탐욕 휴리스틱이다. 같은 입력·정책·seed와 시간 내 탐색 완료 조건에서 같은 후보를 만든다. 날짜마다 실제 수요가 있는 구간을 순회하며, 수요/가능시간/진행표/보존 배정/새 근무 종료/휴게·이동 종료 경계를 처리한다. 전체 사람×눈금×장소의 모든 조합을 미리 생성하지 않는다.

먼저 역할·가능시간 기준 후보가 적은 수요와 책임자 조건을 우선 처리한다. 해당 구간의 책임자가 부족하면 책임자 후보를 우선한다. 책임자가 없을 때 일반 인원으로 책임자 자리를 채워 버리지 않도록 필요한 자리를 남긴다. 각 후보를 권장 교대 길이까지 검토하고, 하드 상한에 닿으면 정수 분 이분 탐색으로 허용되는 종료 시각을 찾는다. 최소 길이를 충족하지 못하는 신규 근무는 추가하지 않는다. 새 자동 근무가 같은 사람·장소·역할로 연속되면 결과에서 병합한다.

균등 우선 점수는 실제 운영시간 내 확인된 가능 분에서 불가/미확인을 뺀 값과 개인 일일/전체 상한을 고려한 용량 대비 배정 분을 이용한다. 원시 칸 수를 공평함의 기준으로 삼지 않는다. 필수 최소시간 부족, 희망시간, 기존 근무 연속성, 선호시간을 후보 점수에 반영한다. `balanced`, `continuous`, `preferred`는 소프트 점수의 가중치를 바꾸며 하드 제약은 동일하다. 특정 사람의 미래 배치 가능성 전체를 최적으로 예약하는 전역 탐색은 아니다.

재실행 기본은 `fill`이며 기존 배정을 보존한다. `all`은 잠기지 않은 배정만 다시 계산한다. `selected`는 지정한 시간 및 선택 장소의 잠금 해제 배정만 재계산하고 범위 밖 조각은 보존한다. 선택 경계가 기존 근무의 바깥 조각을 최소 배정 길이보다 짧게 만들면 해당 기존 근무 전체를 보존하며, 사용자가 범위를 넓혀 다시 시도하도록 결과 설명에 남긴다. 잠금은 모든 모드에서 유지한다.

보존 배정의 실제 충돌·불가·자격·상한 오류 등은 `invalid-fixed`이며 원래 배정을 그대로 반환한다. 채울 수 있는 책임자/필수 최소시간 집계 부족만으로 고정 배정 오류라고 판정하지 않는다. 완성되지 않은 결과는 `partial`, 제한 시간이 끝나면 `timeout`, 취소하면 `cancelled`이다. `complete`도 독립 검증에서 오류나 부족이 발견되면 `partial`로 바꾼다. 상태값에 ‘증명된 불가능’은 없다. 어떤 결과도 전역 최적해나 유일한 불가능 원인을 보장하지 않는다.

기본 탐색 시간은 5,000ms다. 실행 시간과 후보 검사 횟수를 결과에 기록한다. 시간 제한은 탐색 루프에서 확인하며, 입력/최종 검증 시간까지 정확히 중단하는 하드 실시간 기한은 아니다. 완료 직전의 기기 성능 차이 때문에 시간 제한에 걸린 후보는 달라질 수 있다. 실제 UI는 Web Worker를 사용하고 취소 시 Worker를 종료한다. 적용 전 결과 미리보기를 제공하며 편집 내용이 바뀌었다면 과거 결과 적용을 막는다. 계산 취소는 현재 편집 배정을 바꾸지 않는다.

## 확정·이력·출력

정상 확정은 하드 오류와 인원/책임자 부족이 모두 없을 때만 가능하다. 희망 최소시간 등 경고는 남을 수 있다. 확정 시 당시 행사 데이터의 독립된 깊은 사본을 스냅샷으로 저장한다. 새 개정 초안을 만들면 버전이 증가하고 과거 스냅샷과 현재 배열을 공유하지 않는다. Undo/Redo는 배정·일괄 작업을 포함한 로컬 편집 스냅샷이며 위변조 방지 감사 원장이 아니다.

인쇄·개인별표·장소별표·변경 대상·진행표·XLSX는 같은 행사와 검증 결과를 바탕으로 생성한다. 배포용 기본 출력은 내부메모와 가능시간 상세를 제외한다. JSON은 명단·가능시간·내부메모·잠금·확정본을 포함하는 편집용 전체 백업이다. JSON의 행사 ID, 스키마, 앱 버전, 저장 시각, 시간대와 참조 ID를 확인한다. 지원하지 않는 미래 버전의 마이그레이션은 구현하지 않았으며 원본을 바꾸지 않고 거절한다. 브라우저 저장과 파일 백업은 서로 대체 관계가 아니며 영구 보관을 보장하지 않는다.

## 검증 규모와 한계

가상 7일·100명·10장소·30분 눈금, 70개의 8시간 수요(장소별 2명), 일일/전체/연속 상한·휴게30분·이동10분 조건을 자동 테스트한다. 구체적 실행 시간과 브라우저 취소/출력 결과는 실제 실행 기록인 `qa-report.md`에 적는다. 자동 테스트에는 미세 분 경계, 자정 합계, 두 역할의 연속 근무, 잠금, 부분 재배정, 책임자, 전담 진행, 독립 분 단위 오라클의 무작위 문제와 16개 작은 경우의 전수 기준 비교가 포함된다.

탐욕법이므로 미래 희소 인원을 먼저 사용하거나 짧은 잔여 시간을 남겨, 실제로 가능한 완전한 해를 찾지 못할 수 있다. 다른 seed/프리셋/수동 조정이 개선할 수 있으며 조건을 자동 완화하지 않는다. 입력 파일 크기·행·시트 한도는 안전하게 거절할 상한이지 그 크기의 표를 빠르게 편집한다는 성능 보장은 아니다. 실제 시험한 규모보다 큰 경우의 응답성은 별도 검증이 필요하다. PWA 설치와 오프라인 재접속, 온라인 공동편집, 링크를 통한 최신본 동기화, 해외 시간대 변환은 이 구현의 보장 범위가 아니다.
